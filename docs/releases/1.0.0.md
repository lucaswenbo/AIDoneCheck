# AIDoneCheck v1.0.0

AI 说“完成了”。AIDoneCheck 检查证据。

首个稳定版本：为 Codex、Claude Code、Cursor、GitHub Copilot Coding Agent 和使用 AI 编码的开发者提供确定性验收。当前提供中文说明和示例；英文文档与默认语言调整留待后续版本。

## 选择哪个版本

| 引用 | 适合谁 |
|---|---|
| `lucaswenbo/AIDoneCheck@v1.0.0` | 推荐：固定本次稳定版本，主动决定何时升级 |
| `lucaswenbo/AIDoneCheck@v1` | 自动跟随经过发布验证的最新 1.x |
| `lucaswenbo/AIDoneCheck@main` | 开发和测试，不作为普通用户默认引用 |

对供应链锁定要求较高的工作流，可使用本 Release 对应的完整 commit SHA。

## GitHub Action

在你的 Node.js/npm 项目中，先 checkout 完整历史并安装项目依赖，再添加：

```yaml
- uses: lucaswenbo/AIDoneCheck@v1.0.0
  id: verify
```

完整可复制的工作流在 [examples/verify-task.yml](https://github.com/lucaswenbo/AIDoneCheck/blob/v1.0.0/examples/verify-task.yml)。它支持手动运行，使用 `contents: read`、`fetch-depth: 0` 和 `persist-credentials: false`。

Action 自带运行依赖。可选 Browser Check 才会隔离安装固定 Playwright/Chromium，不污染调用者 package.json、package-lock 或 node_modules。BLOCK 后仍保存并上传 Evidence，再让步骤失败。

## 本地 CLI

Node.js >=20，并已安装 npm、Git：

```bash
npm install --global https://github.com/lucaswenbo/AIDoneCheck/releases/download/v1.0.0/aidonecheck-1.0.0.tgz
aidonecheck --version
```

进入你自己的项目后：

```bash
aidonecheck init
aidonecheck doctor
aidonecheck check --base origin/main
aidonecheck report
```

CLI 包是本 Release 的下载附件，**没有发布到 npm registry**；不要用裸 `npx aidonecheck` 猜测包来源。下载附件后可使用 `SHA256SUMS.txt` 验证摘要。

## 本次能力

- committed / staged / unstaged / untracked union，可靠 local / explicit / PR / push diff。
- 指定文件存在与修改要求；脚本执行后重新观察文件和工作区，避免旧状态假通过。
- 实际 test / lint / typecheck / check-types / build，超时、日志截断和尽力清理后代进程。
- PASS / WARN / BLOCK、规范退出码、可解析的单一 JSON 输出。
- 可选 Chromium：可见文本、pageerror、console、最终同源关键资源、全页截图和真实 Trace。
- 原子 latest 报告、独立 Action Evidence、Job Summary、Artifact 和 agent-feedback.md。

## 已验证的失败场景

真实断言失败会 BLOCK，后续检查继续执行；pageerror 会 BLOCK，并保留 browser.png、trace.zip 和报告；配置或浏览器环境缺失是启动错误，不伪造验收结论。发布检查还会独立安装实际 CLI 压缩包并验证 PASS、BLOCK 和 Evidence。

## 边界

主要支持 Node.js/npm、Linux CI、Chromium；Windows 尚未完整验证。不会启动服务器、调用 LLM、自动修代码或自动合并。PASS 只说明当前配置和本次观察通过，不保证软件没有 bug。它会执行项目 npm scripts，不是沙箱；Trace、截图、日志和 Artifact 应视为潜在敏感数据。
