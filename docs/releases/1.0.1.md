# AIDoneCheck v1.0.1

本次为缺陷修复版本，同时提供可直接查看、Fork 后点击复现的六场景中文演示。

## 修复

- Browser 资源错误详细记录达到 200 条后，继续检测后续同源关键资源失败；不能因日志截断把应当 BLOCK 的结果降为 WARN。仍基于最终 URL origin 判断，跨源错误不会因此自动升级为 BLOCK。
- 项目 npm scripts 执行后重新校验 requirements 路径，拒绝脚本新建的外部 symlink；这类错误返回退出码 2，不伪造 PASS。

这两项问题在 v1.0.0 中已复现，并添加了回归测试。建议升级到 v1.0.1；旧的 v1.0.0 tag 保持原样。

## 点击查看或复现

[公开演示](https://github.com/lucaswenbo/AIDoneCheck/actions/workflows/demo.yml) · [中文操作说明](https://github.com/lucaswenbo/AIDoneCheck/blob/v1.0.1/docs/demo.md)

包含健康 PASS、无真实测试 WARN、真实断言失败 BLOCK、pageerror BLOCK、日志上限后的关键资源 BLOCK、外部 symlink 路径错误。每个场景实际运行 Action，再检查 outcome、报告、上传的 Artifact 及下载文件摘要。

有本仓库写权限可直接点击 Run workflow；其他用户先 Fork，在自己的仓库运行。不需要网站、额外 Secrets 或 LLM API。

## 应该用哪个版本

- 推荐 `lucaswenbo/AIDoneCheck@v1.0.1`：固定本次稳定版。
- `@v1`：跟随经过发布验证的 1.x 兼容版本。
- `@main`：开发代码；不作为普通产品接入的默认引用。
- 演示的 `uses: ./`：运行所选仓库提交，自包含且适合 Fork 复现。

本地 CLI：

```bash
npm install --global https://github.com/lucaswenbo/AIDoneCheck/releases/download/v1.0.1/aidonecheck-1.0.1.tgz
aidonecheck --version
```

没有发布到 npm registry；安装包和 SHA256SUMS.txt 位于本 Release 附件。完整用法见中文 README。

## 验证与边界

发布前必须让同一 main 提交的 Test、Browser smoke、Action smoke 和 AIDoneCheck 可复现演示全部成功；发布包再经独立安装测试。发布后从公开下载地址与固定/浮动 Action tag 做消费验证。

主要支持 Node.js/npm、Linux CI 和 Chromium；不自动启动用户服务器、不调用 LLM、不自动修代码、不自动 merge。PASS 只表示本次配置下的验证通过，不保证绝对无 bug。
